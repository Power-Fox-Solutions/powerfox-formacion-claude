01

Qué es Office Scripts y dónde encaja

La idea base TS

Office Scripts es el sistema oficial de Microsoft para automatizar Excel en la nube usando TypeScript. Vive dentro de Excel para la web (también se ejecuta desde Excel Desktop si tu tenant lo permite) y se guarda en tu OneDrive como un archivo .osts.

Sustituye en la práctica a las macros VBA cuando trabajas con libros de Excel Online, y se invoca desde la UI o desde un flujo de Power Automate con la acción Excel Online (Business) → Run script.

Para qué lo usarás de verdad

  • Limpiar y normalizar datasets que llegan sucios (espacios, fechas en texto, duplicados).
  • Generar informes repetitivos: agrupar, totalizar, formatear, exportar.
  • Pegamento para Power Automate: la lógica que el flujo no sabe hacer (bucles complejos, transformaciones, fórmulas masivas).
  • Acciones de un clic publicadas en la cinta para usuarios no técnicos.

Una frase para recordar: Office Scripts es el "VBA moderno" — pero solo para Excel, solo en tu cuenta corporativa, y con un superpoder añadido: se puede llamar desde Power Automate.

Requisitos previos: licencia Microsoft 365 Business Standard / Premium / E3 / E5. La pestaña Automate debe estar habilitada por el admin del tenant. Si no la ves, no es tu Excel — es la política.

02

Anatomía — editor, grabador y archivo .osts

Code Editor

Editor TypeScript dentro de Excel. Autocompletado completo de la API ExcelScript, validación en vivo, ejecución con un clic. No instalas nada — es Monaco (el motor de VS Code) embebido.

Action Recorder

El grabador. Activa, haz clics y ediciones en la hoja, para. Excel te entrega un script TypeScript funcional. Punto de partida ideal antes de personalizarlo a mano.

Archivo .osts

Cada script es un fichero .osts que vive en OneDrive/Documents/Office Scripts. Se puede compartir como cualquier otro archivo, lo que habilita scripts de equipo.

Cómo abrir el editor en 10 segundos

  1. Abre el libro en Excel para la web (excel.cloud.microsoft).
  2. Pestaña Automate en la cinta.
  3. Botón New Script (o Record Actions para grabar).
  4. Aparece el panel del editor a la derecha con un script vacío de plantilla.
  5. Pulsa Run para ejecutar; Save para guardarlo en tu OneDrive.

Estructura mínima de un script

function main(workbook: ExcelScript.Workbook) { // 1. Tomar la hoja activa (o una específica por nombre) const sheet = workbook.getActiveWorksheet(); // 2. Leer / modificar / escribir const rango = sheet.getRange("A1"); rango.setValue("Hola Office Scripts"); // 3. (Opcional) Devolver datos al flujo de Power Automate return rango.getValue(); }

El primer parámetro workbook es siempre el libro donde se ejecuta el script. Si añades más parámetros (tipados), Power Automate los detecta automáticamente y te pide rellenarlos al usar la acción.

03

Office Scripts vs VBA vs Office.js — cuál uso, cuándo

OFFICE SCRIPTS

El sucesor para la nube

TypeScript, async, tipado, multiplataforma (web/desktop/mobile en Excel), invocable desde Power Automate.

  • Pros: moderno, seguro, integrable, sin instalación.
  • Contras: solo Excel, solo tenant M365, sin acceso al sistema.
  • Úsalo cuando: el libro vive en SharePoint/OneDrive y necesitas automatizar o integrar con flows.
VBA

El veterano local

Visual Basic embebido en el archivo (.xlsm). Acceso a Win32, COM y filesystem. No hay TypeScript, no hay Git real.

  • Pros: acceso al sistema, scripts auto-contenidos en el archivo.
  • Contras: solo Excel Desktop Windows, considerado legacy, riesgo de seguridad.
  • Úsalo cuando: el libro vive en local, no se comparte, y necesitas tocar el sistema operativo.

¿Y Office.js / Add-ins?

Es otra cosa: Office.js es para construir add-ins distribuibles (con UI HTML propia) que se instalan en Office. Office Scripts está enfocado a scripts cortos personales o de equipo, no a productos. Si lo que quieres es publicar una herramienta a terceros, mira add-ins; si quieres automatizar tu trabajo o el del equipo, Office Scripts.

La API ExcelScript en 5 minutos

Toda la API cuelga del namespace ExcelScript. La jerarquía importa: Workbook contiene Worksheet, que contiene Range y Table. Lo demás (formato, filtros, gráficos, tablas dinámicas) son métodos sobre esos objetos.

Patrones de lectura/escritura

// Leer un valor escalar const v = sheet.getRange("B2").getValue(); // Leer un rango como matriz 2D (filas × columnas) const matriz: (string | number | boolean)[][] = sheet.getUsedRange().getValues(); // Escribir un rango entero de un golpe (siempre prefiere esto) sheet.getRange("A1:C3").setValues([ ["Producto", "Cantidad", "Total"], ["Café", 10, 35.5], ["Té", 7, 21.0] ]); // Iterar por filas: rápido si lees primero, escribes después const filas = sheet.getUsedRange().getValues(); for (let i = 1; i < filas.length; i++) { filas[i][2] = (filas[i][1] as number) * 1.21; } sheet.getUsedRange().setValues(filas);

Regla de oro de rendimiento: cada llamada a la API tiene latencia de red. Lee todo lo que necesites a una matriz, opera en memoria en TypeScript, y escribe el resultado en una sola operación. Un bucle que lea/escriba celda a celda puede tardar minutos donde un setValues tarda milisegundos.

6 ejemplos prácticos listos para copiar

1

Limpiar un dataset (trim, fechas, duplicados)

Datos
Demuestra · lectura/escritura masiva · uso de Set y normalización en memoria

Toma una hoja con datos sucios típicos: espacios extras, mayúsculas inconsistentes, fechas como texto, duplicados por email. Devuelve la misma hoja normalizada y un contador de cambios.

Datos demo: abre limpiar-dataset-demo.csv en Excel. 22 filas con todos los problemas: emails con espacios y mayúsculas, nombres con dobles espacios, fechas DD/MM/YYYY, 5 duplicados y 2 emails vacíos. Tras ejecutar el script deben quedar 15 filas limpias.

Trampa real (la vimos en clase): al abrir el CSV, Excel auto-convierte 15/01/2025 a fecha real. Entonces getValues() devuelve un número serial, no un string, y .split("/") revienta con "split is not a function". El helper aIso() de arriba detecta el tipo (typeof v === "number") y convierte el serial a ISO; si llega como texto DD/MM/YYYY también lo cubre. Por eso el código real necesita esa función — el grabador no te la genera.

function main(workbook: ExcelScript.Workbook) { const sheet = workbook.getActiveWorksheet(); const usado = sheet.getUsedRange(); const filas = usado.getValues(); const [cab, ...datos] = filas; const idxEmail = cab.indexOf("Email"); const idxNombre = cab.indexOf("Nombre"); const idxFecha = cab.indexOf("FechaAlta"); const vistos = new Set<string>(); const limpias = datos.filter(f => { const mail = String(f[idxEmail] ?? "").trim().toLowerCase(); if (!mail || vistos.has(mail)) return false; vistos.add(mail); f[idxEmail] = mail; f[idxNombre] = String(f[idxNombre] ?? "").trim().replace(/\s+/g, " "); f[idxFecha] = aIso(f[idxFecha]); return true; }); usado.clear(ExcelScript.ClearApplyTo.contents); sheet.getRangeByIndexes(0, 0, 1, cab.length).setValues([cab]); sheet.getRangeByIndexes(1, 0, limpias.length, cab.length).setValues(limpias); // La columna FechaAlta queda como texto ISO; forzamos formato texto sheet.getRangeByIndexes(1, idxFecha, limpias.length, 1).setNumberFormat("@"); console.log(`Filas finales: ${limpias.length} (de ${datos.length})`); } // Convierte cualquier representación de fecha a "YYYY-MM-DD" function aIso(v: string | number | boolean): string { if (typeof v === "number") { // Excel guarda fechas como serial; 25569 = días entre 1900-01-01 y 1970-01-01 const ms = Math.round((v - 25569) * 86400 * 1000); return new Date(ms).toISOString().slice(0, 10); } const s = String(v).trim(); const m = s.match(/^(\d{1,2})\/(\d{1,2})\/(\d{4})$/); if (m) return `${m[3]}-${m[2].padStart(2,"0")}-${m[1].padStart(2,"0")}`; return s; // ya viene en ISO o formato desconocido — lo dejamos tal cual }

Resumen mensual con totales por categoría

Reporting
Demuestra · agregaciones en TypeScript · escritura de hoja nueva
function main(workbook: ExcelScript.Workbook) { const origen = workbook.getWorksheet("Movimientos"); const rows = origen.getUsedRange().getValues(); const [cab, ...datos] = rows; const iCat = cab.indexOf("Categoria"); const iImp = cab.indexOf("Importe"); const totales = new Map<string, number>(); for (const f of datos) { const cat = f[iCat] as string; const imp = f[iImp] as number; totales.set(cat, (totales.get(cat) ?? 0) + imp); } // Crea (o reemplaza) la hoja de salida workbook.getWorksheet("Resumen")?.delete(); const out = workbook.addWorksheet("Resumen"); const filas: (string|number)[][] = [["Categoría", "Total €"]]; for (const [cat, t] of totales) filas.push([cat, t]); out.getRangeByIndexes(0, 0, filas.length, 2).setValues(filas); workbook.addTable(out.getRange("A1").getResizedRange(filas.length-1, 1), true) .setPredefinedTableStyle("TableStyleMedium2"); }

Formato condicional para alertas

UX
Demuestra · ConditionalFormat aplicado por código (regla cellValue)
function main(workbook: ExcelScript.Workbook) { const sheet = workbook.getActiveWorksheet(); const col = sheet.getRange("D2:D1000"); col.getConditionalFormats().forEach(c => c.delete()); const rojo = col.addConditionalFormat(ExcelScript.ConditionalFormatType.cellValue); rojo.getCellValue().setRule({ formula1: "=0", operator: ExcelScript.ConditionalCellValueOperator.lessThan }); rojo.getCellValue().getFormat().getFill().setColor("#FFC7CE"); rojo.getCellValue().getFormat().getFont().setColor("#9C0006"); const verde = col.addConditionalFormat(ExcelScript.ConditionalFormatType.cellValue); verde.getCellValue().setRule({ formula1: "=10000", operator: ExcelScript.ConditionalCellValueOperator.greaterThan }); verde.getCellValue().getFormat().getFill().setColor("#C6EFCE"); }

Script con parámetros + retorno (callable desde Power Automate)

Integración
Demuestra · firma de main con args tipados · retorno usable como salida

Cualquier parámetro que añadas a main aparece automáticamente como input de la acción Run script en Power Automate. El return queda como output del paso, encadenable a otras acciones.

function main( workbook: ExcelScript.Workbook, cliente: string, desde: string, // "2026-01-01" hasta: string ): { totalFacturado: number; lineas: number } { const sheet = workbook.getWorksheet("Facturas"); const rows = sheet.getUsedRange().getValues(); const [cab, ...datos] = rows; const iCli = cab.indexOf("Cliente"); const iFec = cab.indexOf("Fecha"); const iImp = cab.indexOf("Importe"); const filtradas = datos.filter(f => f[iCli] === cliente && f[iFec] >= desde && f[iFec] <= hasta ); const total = filtradas.reduce((acc, f) => acc + (f[iImp] as number), 0); return { totalFacturado: total, lineas: filtradas.length }; }

En el flujo, esos campos aparecen como inputs en la acción Excel Online (Business) → Run script. El output es un objeto JSON que puedes mapear directo a un correo, una tarjeta de Teams o una fila de Dataverse.

Integración con Power Automate — el verdadero superpoder

Sola, Office Scripts es una macro moderna. Combinada con Power Automate, se convierte en el motor de cálculo serverless del flow. El flow orquesta (correo, aprobación, SharePoint, Teams) y delega en el script lo que el flow no sabe hacer (transformaciones complejas).

Trigger PA
→
Get file (SharePoint)
→
Run script
→
Send email / Teams

Cómo se conectan

  1. Crea un flow en Power Automate.
  2. Añade la acción Excel Online (Business) → Run script.
  3. Selecciona Location, Document Library, File y Script.
  4. Si tu main tiene parámetros, aparecen como campos del paso.
  5. Encadena la salida del script al siguiente paso (correo, Teams, Dataverse).

Tipos válidos como parámetros

  • string, number, boolean, Date.
  • Arrays de los anteriores.
  • Objetos con campos tipados (Power Automate los rellena con un cuadro de "Parameters").

Lo que no funciona: tipos del SDK de Excel (Workbook, Range) más allá del primer parámetro. No puedes pasar una hoja entera como input — pasa el nombre y la lees dentro.

Caso típico: informe semanal automatizado

  1. Recurrence: cada lunes a las 7:00.
  2. Run script sobre Ventas.xlsx en SharePoint, parámetros desde / hasta calculados con addDays.
  3. El script construye la hoja Resumen y devuelve { total, top3 }.
  4. Send an email (V2) con el JSON renderizado en HTML y el archivo adjunto.

Truco: si tu flow se queda corto (timeout 6 min), no partas el script en flows pequeños — sube todo el bucle al script, que tiene 5 min en flows estándar pero ejecuta TS puro a velocidad nativa. Lo que tarda 5 minutos en PA puede tardar 5 segundos en TS.

07

Claude Code como copiloto de Office Scripts

Claude Code escribe, refactoriza y traduce TS de Excel

El editor de Office Scripts en la web no tiene IA propia. La forma profesional de trabajar es:

  • Grabas con Action Recorder un primer borrador.
  • Pegas el .osts en tu repo local (es un archivo de texto, vive bien en Git).
  • Pides a Claude Code que lo refactorice, generalice o traduzca un VBA viejo a Office Scripts.
  • Pegas el resultado de vuelta en el editor de Excel y ejecutas.

Claude conoce la API ExcelScript bien: distingue setValues de setValue, recuerda que getUsedRange puede devolver null en hojas vacías y aplica los patrones de rendimiento sin que se lo pidas.

3 prompts que de verdad usarás

Refactor del recorder

"Toma este script grabado con Action Recorder, generalízalo para que funcione con cualquier hoja activa (no la específica que grabé) y añade tipos explícitos en lugar de any."

Migrar VBA

"Traduce esta macro VBA a Office Scripts. Mantén la lógica idéntica pero usa lectura/escritura por matrices en vez de celda a celda. Devuelve solo el TypeScript final."

Detector de bugs

"Revisa este script y dime: ¿qué pasa si la hoja está vacía, si la columna falta, si hay un valor no numérico? Añade los chequeos mínimos sin sobreingeniería."

Workflow recomendado en S4-miércoles

  1. En Excel: graba con Record Actions el flujo manual.
  2. Copia el TS al editor de tu IDE (en /sesiones/s4-miercoles/scripts/ por ejemplo).
  3. Pide a Claude Code el refactor + tipado fuerte.
  4. Pide tests mentales: "dame 3 datasets que romperían este script".
  5. Versiona el .osts en Git para tener historial real (cosa que Excel no te da).
  6. Pegado de vuelta al editor + Save.

Pregunta para abrir debate en clase: ¿qué te ata a VBA en tu equipo hoy? Si es solo costumbre, este es el momento de migrar. Si es algo concreto (UDFs, acceso al sistema, libros muy grandes en local), Office Scripts no es el reemplazo — y conviene saberlo antes de prometerlo.
